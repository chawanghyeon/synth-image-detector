# 재시작 이후 실험 기록 (2026-10-05)

목표: 최대한 가벼운 방법으로, 학습에 없던 최신 생성기의 이미지를 실제 사진 오탐 없이 걸러낸다. 출발 가설은 "확산 모델 특유의 노이즈 흔적이 이미지에 남는다"였다.

## 공통 설정

- **데이터:** [OpenFake v2](https://huggingface.co/datasets/ComplexDataLab/OpenFake) (CC BY-NC 4.0).
  - train: shard 3개로 시작해 나중에 6개로 늘렸다. 생성기 73종, 실제 사진은 LAION·Pexels.
  - validation: shard 1개.
  - test: shard 1개, 6,872장. 학습에 없는 생성기 20종의 AI 이미지 3,466장과, 학습에 없는 출처의 실제 사진 3,406장(ImageNet 2,227, DOCCI 1,179)으로 구성된다.
  - 추가 실제 사진: COCO val2017, Flickr30k, Open Images(이미 512px로 리사이즈된 사본).
- **전처리:** 이미지마다 원본 해상도에서 최대 512px 조각을 무손실로 잘라 썼다. 리사이즈는 하지 않았다.
- **학습 증강:** 두 클래스 모두에 같은 확률로 적용했다. 30% 확률로 0.5–1.5배 리사이즈, 80% 확률로 JPEG Q60–100. 파일 형식이 지름길이 되지 않게 하기 위해서다. 테스트에서 AI 이미지의 70%는 JPEG였고, "원본 파일이 JPEG가 아님" 하나만으로 얻는 AUROC는 0.65였다.
- **평가:** 임계값은 validation 실제 사진의 오탐 1% 지점으로 정하고, test에서는 그대로 고정했다. 표의 FPR/TPR은 그 고정 임계값에서의 값이다. JPEG·축소 조건은 테스트 이미지를 다시 변환한 것이다.

## 해석

1. **노이즈 가설은 부분적으로 맞다.** 신경망 없이 픽셀 차분의 마르코프 전이 통계(SPAM)만으로도, 처음 보는 생성기 20종을 실제 사진 오탐 0.3%에서 절반가량 잡았다. 수식을 직접 정한 이전 시도(FFT, 잔차 통계, 격자 위상, VAE 왕복)는 운영 기준을 넘지 못했다. 반면 고차원 공동출현 통계를 만들고 경계는 학습기에 맡기니 동작했다.
2. **가장 큰 개선은 실제 사진의 다양성에서 나왔다.** COCO 5천 장을 추가하자 원본 AUROC가 0.897에서 0.941로 올랐고, 축소 조건의 오탐률은 24%에서 5%로 떨어졌다. 같은 출처(LAION·Pexels)로만 학습하면 validation 점수만 오르고 test는 오르지 않는 과적합이 반복됐다. 이미 리사이즈된 사진(Open Images)을 넣으면 원본 성능이 떨어졌다.
3. **재압축과 축소에 약하다.** 노이즈 흔적은 JPEG 50이나 1/2 축소를 거치면 대부분 사라진다. 순위 정보(AUROC 0.7)는 남지만, 원본 기준 임계값으로는 거의 탐지되지 않는다. 변환 T가 두 분포를 가깝게 만들면 어떤 판정 규칙도 TPR − FPR ≤ TV(T#P_fake, T#P_real)를 넘을 수 없다.
4. **CNN(NoiseNet)은 압축과 축소에 더 강하다.** 실제 사진을 다양하게 넣어 다시 학습하자 원본 AUROC가 0.814에서 0.931로, JPEG 50은 0.863, 절반 축소는 0.834가 됐다. SPAM과 섞으면 원본 성능은 SPAM 수준을 유지하면서 압축 조건이 개선된다. torch 없이 돌도록 ONNX로 내보내 onnxruntime(약 15MB)으로 실행한다. 파이썬과 ONNX의 출력 차이는 최대 3e-6이었다.
5. **생성기별 편차가 크다.** Midjourney 7, Ideogram, Lumina는 90% 이상 잡힌다. FLUX.2-klein, Seedream 5, Recraft는 0–15%다.

## 시도하지 않은 것

- DINOv2-small 선형 탐침은 코드를 만들었지만 실행하지 않았고, 정리하면서 삭제했다. 이유는 두 가지다. 이전 프로젝트에서 고정 백본과 선형 헤드 계열(PE-Linear)이 일반 이미지로 전이되지 않았다. 그리고 2,200만 파라미터는 "가볍게"라는 목표와 맞지 않는다.
- 스크린샷, 편집 사진, SNS 재업로드 이미지로 별도 오탐 평가를 하지 않았다.

## 새 가설 검증 (2026-10-05, 탈락)

기존 방법과 다른, 물리·생성 과정 기반의 가설 두 개를 통과/탈락 기준을 먼저 정한 뒤 검증했다.

- **기준:** validation AUROC ≥ 0.70. test(새 생성기)에서 원본 ≥ 0.70, JPEG 75·절반 축소에서도 ≥ 0.65. 이미지 크기만으로 얻는 AUROC보다 확실히 높을 것.
- **데이터:** 원본 크기 이미지, 클래스당 300장, validation과 test 각각.

| 가설 | validation | test 원본 | test JPEG 75 | test 절반 축소 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| **렌즈 지문:** 실제 사진에는 R·B 채널이 G 대비 방사형으로 어긋나는 색수차 장이 있다. 학습 없음, 방사형 모델 적합도 R² | 0.613 | 0.799 | 0.786 | 0.716 | 탈락 |
| **생성 순서 지문:** 스케일 간 위상 결합(log-Gabor, 1:1과 1:2 결합) + 로지스틱 회귀 | 0.673 | 0.645 | 0.641 | 0.701 | 탈락 |
| (통제) 이미지 크기·비율만 사용 | 0.704 | 0.849 | — | — | — |

렌즈 지문은 test에서 JPEG에 거의 영향받지 않았다(0.799 → 0.786). 하지만 점수가 이미지 픽셀 수와 상관 0.54로 엮여 있었고, test에서 크기만 쓴 기준선(0.849)보다 낮았다. 크기 구간을 나눠 보면 validation에서는 AUROC 0.60–0.65였다. 크기를 통제하면 남는 신호는 약하다(크기 위에 얹었을 때 +0.02–0.03). 휴대폰과 보정 소프트웨어가 색수차를 이미 지우는 것으로 보인다.

교훈: 데이터셋의 크기·출처 차이가 새 신호처럼 보이기 쉽다. 앞으로 새 가설은 반드시 크기·출처를 통제한 평가로 판정한다. 실험 코드는 저장소에 넣지 않았다.

### 2차: 전역 물리 일관성 가설 (크기 맞춤 평가)

렌즈 실험의 교훈에 따라 판정 장치를 고쳤다. 로그 픽셀 수 구간마다 실제·AI 이미지를 같은 수만 남긴 **크기 맞춤 부분집합**에서만 AUROC를 쟀다(validation 358장, test 130장). 점수 방향과 작은 로지스틱 회귀는 validation에서만 정했다. test 130장은 표준오차가 약 ±0.05로 작은 표본이다.

패치 반복 통계는 validation 기준을 넘지 못했다. 하지만 test에서 JPEG·축소 후에도 성능이 유지된 유일한 신호다. 다만 test를 이미 여러 번 봤으므로, 이 신호를 더 다듬는다면 **한 번도 보지 않은 새 holdout**(다른 OpenFake test shard, Reddit 실전 세트)으로만 최종 판정해야 한다.

### 3차: 패치 반복 신호 정밀화 → 새 holdout 1회 판정 (탈락)

2차에서 유일하게 압축에 버틴 패치 반복 신호를 다듬었다.
- **특징:** 특징 80개 = 패치 5·7px × (인접 / 비중첩 / 2배 축소 스케일 최근접 거리, 비중첩 대비 축소 스케일 거리 비) × 분위수 5개 × 휘도·색차.
- **학습:** 학습 crop에서 크기를 맞춘 3,000장으로 boosting을 학습했다. 5-fold CV AUROC 0.887, validation(크기 맞춤) 0.842로 2차의 0.65보다 크게 올랐다.
- **판정:** 모델을 고정한 뒤 **한 번도 보지 않은 holdout에서 단 1회** 판정했다. 미리 정한 기준은 OpenFake 새 test shard에서 원본 ≥ 0.75, JPEG 75 하락 ≤ 0.03이었다.

| holdout (크기 맞춤 AUROC) | 원본 | JPEG 75 | 절반 축소 |
| --- | ---: | ---: | ---: |
| OpenFake test shard 1 (108장) | **0.830** | 0.693 | 0.627 |
| OpenFake Reddit 실전 세트 shard 0 (282장) | 0.768 | 0.678 | 0.731 |

**탈락.** 원본 성능은 기준을 넘었지만 JPEG 하락이 0.14였다. 작은 패치와 통계를 더하자 미세 노이즈를 잡게 되면서 결국 또 하나의 노이즈 탐지기가 됐다. 특징 4개짜리 단순 버전은 JPEG에 강했지만(0.72 → 0.71) 정확도가 낮았다. **정확도와 압축 강건성의 교환 관계**가 이번에도 나타났다. 압축에 강한 신호는 정보량이 적은 큰 스케일 구조에만 남는다는 해석과 맞는다.

**같은 holdout에서 현재 서버 앙상블(SPAM + NoiseNet)의 성능.** `ai_score > 0.5` 기준이며, 크기 맞춤 AUROC와 전체 AUROC를 함께 적었다.

| holdout | 원본 | JPEG 75 | 절반 축소 |
| --- | --- | --- | --- |
| OpenFake test shard 1 (1,175장) | 0.880 / 전체 0.963, FPR 0.0%, TPR 54.1% | **0.898** / 0.884, TPR 15.7% | 0.883 / 0.751, TPR 36.0% |
| Reddit 실전 세트 (1,199장) | 0.843 / 전체 0.944, FPR 1.0%, TPR 34.7% | 0.787 / 0.915, TPR 11.7% | 0.773 / 0.804, TPR 10.4% |

현재 서버는 모든 조건에서 패치 반복 모델보다 높았다. JPEG 75에서도 순위 정보(AUROC 0.79–0.90)는 대부분 남는다. 문제는 고정 임계값 0.5에서 점수가 낮아져 탐지율이 떨어지는 것이다. Reddit 실전 세트는 실제로 유통된 이미지라 학습에 쓴 데이터와 분포가 다른데, 거기서도 전체 AUROC 0.944, 실제 사진 오탐 1.0%였다. holdout 데이터는 사용 후 삭제했다.

### 4차: 압축 강도별 임계값, 압축 전용 모델, 촬영 파이프라인 일관성 (모두 탈락)

새 holdout(OpenFake test shard 2, Reddit 실전 shard 1)에서 각 가설을 1회씩 판정했다.

- **압축 강도별 임계값.** JPEG 양자화 표로 품질을 추정해(오차 0) 품질 구간별로 1% 오탐 임계값을 다시 정했다. JPEG 75 탐지율은 OpenFake 13.0% → 17.3%, Reddit 12.3% → 19.0%로 기준(2배)에 못 미쳤다. 탈락. 품질이 낮아져도 실제 사진의 점수는 거의 그대로이고, AI 이미지의 점수만 실제 사진 쪽으로 내려왔다. 압축이 정보를 실제로 지운다는 뜻이다.
- **압축 이미지 전용 SPAM 모델**(Q ≤ 85 증강본만 학습). validation JPEG 75에서 AUROC 0.885로 범용 모델(0.891)보다 낮았다. 탈락.
- **촬영 파이프라인 일관성.** 실제 사진은 영역과 무관하게 하나의 센서·처리·압축을 거친다는 가설로, 영역 정체성이 저수준 통계를 추가로 설명하는지(η²)를 쟀다. 핵심 특징 η²의 단독 AUROC는 0.52로 신호가 없었다. holdout 원본 0.626, JPEG 75 0.477. 탈락.

지금까지의 정리: 저수준 신호(노이즈·물리)는 모두 압축에 무너졌다. 남은 범용 후보는 의미 수준 특징이다.

### 서버 반영 (2026-10-06)

결합 모델(SPAM + NoiseNet + DINOv3-B 의미 탐지기)을 서버에 넣었다. 새로 학습한 모델은 없고, 정규화 상수와 임계값만 다시 계산했다.
- **기준값 계산:** OpenFake validation 원본 이미지에서 정규화 상수와 임계값을 다시 계산했다. 최종 판정 때는 holdout2를 썼기 때문에, 서버 버전은 판정한 버전과 정규화 상수만 다르다.
- **검증:** 그래서 서버를 그대로 한 번도 안 쓴 새 데이터(OpenFake test shard 4, Reddit shard 3)로 다시 평가했다(`reports/shipped_eval.json`). 기준은 `ai_score > 0.5`이다.

  - **Reddit:** 원본 0.951 / 1.2% / 60.5%. JPEG 75는 0.918 / 0.0% / 36.0%. SNS식은 0.861 / 3.7% / 48.5%.
  - **이전 서버와 비교:** Reddit 원본 탐지가 34.7%에서 60.5%로 올랐다.
- **비용:** CPU 3MP 이미지당 약 0.7초, 최대 메모리 약 1.1GB, 모델 337MB.

### 7차: 잠재공간 통계 가설 (2026-10-08, 탈락)

- **가설:** 확산 모델이 틀리는 부분은 VAE 잠재 지도(픽셀 8배 축소)에 있다. 잠재 지도의 가장 촘촘한 무늬도 픽셀로는 16px 주기라서 JPEG에 살아남을 것이다.
- **방법:** 이미지를 SD VAE(4채널)와 FLUX.1 VAE(16채널, Z-Image-Turbo 저장소본)로 인코딩했다. 잠재 지도에서 채널별 방사형 파워 스펙트럼, 채널 간 상관(원본·고역), 채널 평균·표준편차를 뽑아 로지스틱 회귀로 판정했다.
  - **대조군:** 같은 통계를 8배 평균 축소한 픽셀 이미지에서 계산했다.
  - **데이터:** 학습은 크기 맞춤 2,000장(train + COCO·Flickr30k)이다. 채점은 OpenFake test(새 생성기)의 크기 맞춤 706장과 무작위 600장이다.
- **미리 정한 기준:** 크기 맞춤 test AUROC ≥ 0.80, JPEG 75 하락 ≤ 0.03, 픽셀 대조군보다 +0.03 이상.

| 특징 | 원본 (크기 맞춤 / 무작위) | JPEG 75 | 절반 축소 |
| --- | ---: | ---: | ---: |
| SD 잠재 | 0.633 / 0.603 | 0.543 / 0.589 | 0.530 / 0.448 |
| FLUX 잠재 | **0.714** / 0.658 | 0.589 / 0.583 | 0.602 / 0.562 |
| SD + FLUX | 0.710 / 0.665 | 0.580 / 0.591 | 0.595 / 0.565 |
| 픽셀 8배 축소 (대조군) | 0.537 / 0.524 | 0.534 / 0.518 | 0.551 / 0.422 |

**탈락.** 원본 0.714로 기준에 못 미쳤고, JPEG 75에서 0.125 떨어졌다. 픽셀 대조군보다는 높았지만(0.537), 16px 이상 큰 스케일의 통계에는 실제 사진과 AI 이미지의 차이가 거의 없었다(대조군 0.52–0.55). 잠재 특징이 잡은 신호는 인코더가 미세 질감을 채널에 담은 것으로 보이며, 그래서 다시 JPEG에 무너졌다. 즉, 확산 모델은 큰 스케일의 저수준 통계를 이미 실제 사진과 거의 똑같이 맞춘다. 실험 코드는 저장소에 넣지 않았다.

### 8차: 의미적 '놀람' 가설 (2026-10-08, 탈락)

- **가설:** 실제 사진에서는 DINOv3 조각 벡터가 주변 조각들로부터 일정한 방식으로 예측된다. AI 이미지는 부분마다 그럴듯하지만 조각 사이의 관계가 다를 것이다.
- **방법:**
  - DINOv3-B의 6층·12층 조각 벡터를 PCA 64차원으로 줄였다.
  - **실제 사진 2,000장만으로** 주변 8개 조각에서 가운데 조각을 예측하는 ridge 회귀와, 이미지 평균에서 벗어난 정도를 학습했다.
  - 예측 오차 분포의 통계 약 30개를 판정 점수로 썼다.
  - 문헌상 가장 가까운 것은 CINEMAE(arXiv 2511.06325)다. 다만 그쪽은 픽셀을 재구성하고 AI 이미지로 학습한다.
- **비교:** 같은 validation 600장으로, DINOv3 조각 벡터의 평균·표준편차만 쓴 로지스틱 회귀를 대조군으로 학습했다.

| test (새 생성기) | 놀람 무학습 | 놀람 + 600장 학습 | 대조군 (평균·표준편차, 600장) |
| --- | ---: | ---: | ---: |
| 크기 맞춤 원본 | 0.513 | 0.379 | **0.938** |
| 크기 맞춤 JPEG 75 | 0.509 | 0.379 | 0.850 |
| 크기 맞춤 절반 축소 | 0.600 | 0.544 | 0.902 |
| 무작위 원본 | 0.405 | 0.423 | 0.867 |

**탈락.** 놀람 통계는 무작위 수준이었다. validation 생성기에서 정한 방향이 새 생성기에서는 오히려 뒤집혔다(0.38). 조각 사이의 관계에는 일관된 차이가 없었다.

반면 대조군 결과는 주목할 만하다. **DINOv3 특징 평균에 600장만 학습한 선형 분류기가 처음 보는 생성기에서 0.938**을 냈다. 구분 정보는 조각 간 구조가 아니라 특징 자체에 들어 있다. 이는 대형 웹 사전학습 모델이 이미 AI 이미지를 구분하는 방향을 알고 있다는 문헌 보고(FGTS, Simplicity Prevails)와 맞는다. 실험 코드는 저장소에 넣지 않았다.

### 9차: 방해 공간 제거 탐침 (2026-10-08, 탈락. 대신 실제 사진 출처 이동 문제를 확인)

- **가설:** DINOv3 특징의 AI 방향에는 압축·축소·사진 출처에 따른 변화가 섞여 있다. 실제 사진만으로 이 "방해 공간"을 추정해 직교 투영으로 제거하면, 압축에 강하고 범용적인 탐침이 된다.
- **방법:**
  - **열화 공간:** 출처별 실제 사진 250장 × 4개 출처에 학습 전용 열화(JPEG 60·90, 0.6·0.8배 축소, 블러, WebP 80)를 걸었다. 특징 변화량의 상위 주성분 k개(4, 16, 64)를 열화 공간으로 삼았다. 시험용 변환인 JPEG 75와 절반 축소는 일부러 쓰지 않았다.
  - **출처 공간:** 실제 사진 출처(laion, pexels, coco, flickr30k)를 가르는 LDA 방향 3개를 썼다.
  - **탐침:** 투영 후 validation 600장으로 로지스틱 회귀를 학습했다. 8차의 대조군과 같은 조건이다.

| 크기 맞춤 test | 원본 AUROC | JPEG 75 AUROC | 절반 축소 AUROC |
| --- | ---: | ---: | ---: |
| 투영 없음 | **0.938** | 0.850 | **0.902** |
| 열화 4 + 출처 | 0.924 | 0.853 | 0.895 |
| 열화 16 + 출처 | 0.909 | 0.861 | 0.891 |
| 열화 64 + 출처 | 0.907 | **0.864** | 0.889 |
| 출처만 | 0.938 | 0.851 | 0.903 |

**탈락.** JPEG 75는 최대 +0.014로 기준(+0.03)에 못 미쳤고, 원본은 0.014–0.031 떨어졌다.

**더 중요한 발견은 실제 사진 출처 이동이다.** validation 실제 사진(LAION·Pexels) 기준 오탐 5% 임계값을 test에 그대로 쓰면, test 실제 사진(ImageNet·DOCCI)의 **67%가 AI로 판정됐다.** 순위(AUROC 0.94)는 맞지만, 실제 사진의 점수 수준 자체가 출처에 따라 크게 달라진다. 학습 출처들 사이의 차이를 지워도(LDA) 처음 보는 출처의 이동은 막지 못했다. 실사용에서 범용성을 가로막는 핵심 병목은 압축보다 **처음 보는 실제 사진 출처에서의 오탐**이다. 문헌의 같은 보고로, OpenFake로 학습한 모델이 최신 폰 사진을 실제로 맞힌 비율이 29.7%였다(SSAFE). 실험 코드는 저장소에 넣지 않았다.

### 10차: 실제 사진 출처 하나 빼기 (2026-10-08)

- **질문:** 학습에 없던 실제 사진 출처에서 오탐이 유지되는가?
- **방법:** 실제 사진 출처 6개(laion, pexels, coco, flickr30k, imagenet, docci)에서 각 600장을 썼다. 하나를 빼고 나머지 5개 + OpenFake train AI 2,000장으로 DINOv3 평균·표준편차 탐침을 학습했다. 임계값은 학습 출처의 남겨 둔 실제 사진에서 오탐 1%로 정했다. 비교한 방법은 그대로, 출처 균형 가중, 최악 출처 가중(group DRO), 실제 사진 변이의 상위 주성분 8·32·128개 제거, 그리고 조합이다.
- **미리 정한 기준:** 빠진 출처 중 최악 오탐을 절반으로 줄일 것. 새 생성기 탐지 하락은 5점 이내.

| 빠진 출처 | 오탐 (오탐 1% 임계값) | 새 생성기 탐지 | AUROC |
| --- | ---: | ---: | ---: |
| laion | **68.2%** | 92.3% | 0.800 |
| pexels | 5.7% | 68.0% | 0.936 |
| docci | 2.8% | 67.9% | 0.935 |
| coco | 1.2% | 66.3% | 0.960 |
| flickr30k | 0.0% | 69.5% | 0.995 |

### 23차: PE-Core-G → PE-Core-L 증류 (2026-10-09)

- **교사:** 20차의 PE-Core-G 선형 탐침이다. 각 학습 이미지의 깨끗한 원본에 대한 점수를 썼고, 5겹 교차 예측으로 계산해 자기가 본 이미지는 채점하지 않게 했다(`kaggle/distill/teacher.npz`).
- **학생:** PE-Core-L14-336이다. 마지막 8개 블록, attention pooling, norm, 선형 헤드를 학습했다.
  - 이미지: 학습 12,979장(20차 학습 15,000장 중 임계값용 실제 사진 20% 제외)
  - 입력: 25%는 원본, 35%는 JPEG 50–95, 40%는 SNS식 사본(0.5–1배 + JPEG 60–90)
  - 학습량: 배치 32(실제·AI 반반), 1,500 step(약 4 epoch), AdamW(블록 2e-5, 헤드 1e-3)
  - 시간: Kaggle T4 한 장당 약 55분
- **학생 두 개:**
  - `distill`: 0.5 × 정답 BCE + 0.5 × 교사 확률 BCE
  - `labels`: 정답만 (대조군)
- **평가:** 20차와 같은 test 6,000장(새 생성기 AI 2,300장, 실제 3,700장)이다. 실행은 `scripts/eval_distill.py`로 했다.

| --- | --- | --- | --- | --- |

- **작은 모델을 압축 사본으로 미세조정하는 것만으로 고정된 19억 모델을 넘었다.** 압축 조건에서 +2–4점이었다. 학생은 CPU에서 장당 약 0.44초다(22차, 백본 기준).
- **교사의 몫은 작다.** 두 학생의 차이는 대부분 1점 이내였다. 예외는 Recraft-v3 원본 탐지(distill 89% 대 labels 58%)로, 교사가 이 생성기에서 도움이 됐다. 대신 distill 학생은 WikiArt 원본 오탐이 3.2%로 labels(0.3%)보다 높았다.
- **남은 약점(distill, 고정 임계값):** recraft-v3(JPEG 75 76%, SNS 82%), gpt-image-2(81–88%), flux.2-klein-9b SNS 83%. 실제 이미지 오탐은 출처별 0–3.2%였다.
- **주의:** test는 학습과 같은 데이터셋 계열이다(OpenFake·WikiArt·ImageNet-R·CC3M). 다른 생성기와 실제 유통 이미지(Codex, Reddit)로 다시 확인해야 한다.
