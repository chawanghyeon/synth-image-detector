# 최종 검토와 통합 계획: 가볍고 빠른 범용 AI 이미지 탐지기 (2026-10-06)

먼저 결론입니다.

- **"기존 논문을 모두, 압도적으로 이긴다"는 주장은 세울 수 없습니다.** 어느 데이터셋에서나 1위인 탐지기는 아직 없습니다. 압축이 심하거나 공격자가 탐지기를 알고 공격하면 원리적인 한계도 있습니다.
- **현실적으로 이길 수 있는 주장은 이것입니다.** "모델 100MB 이하, CPU에서 이미지 1장당 0.15초 이하인 탐지기 중 1위. 그리고 10–50배 큰 공개 탐지기들보다도 최신 생성기와 SNS 이미지에서, 실제 사진 오탐을 1%로 고정했을 때 더 많이 잡는다."
- **가는 길은 하나로 정리됩니다.**
  1. 평가부터 바로잡습니다.
  2. 작은 모델(DINOv3 ViT-S)을 끝까지 학습시킵니다. 이때 데이터를 크게 늘리고, 큰 모델의 판단을 작은 모델에 옮겨 담는 "증류"를 같이 씁니다.
  3. 미리 공개한 시험 묶음으로 한 번만 판정합니다.
- **비용과 기간:** 연구용 트랙 현금 약 $400–900, 8–10주. 상업 서비스용은 데이터를 다시 만들어야 해서 약 $1–2k가 더 들고, 법률 검토가 필요합니다.

## 1. 용어 (처음 한 번만 설명)

| 용어 | 뜻 |
|---|---|
| AUROC | 실제 사진과 AI 이미지를 점수 순서로 얼마나 잘 가르는지. 0.5는 무작위, 1.0은 완벽 |
| TPR@1%FPR (오탐 1% 탐지율) | 실제 사진 100장 중 1장만 AI로 잘못 판정하도록 기준선을 정했을 때, AI 이미지를 잡는 비율. 서비스에서 가장 중요한 숫자 |
| 고정 임계값 | 기준선을 우리 검증셋에서 한 번 정하고, 모든 시험셋에 그대로 쓰는 방식. 시험셋마다 다시 맞추면 점수가 부풀려짐 |
| 크기 맞춤 AUROC | 실제와 AI의 이미지 크기 분포를 맞춘 부분집합에서 잰 AUROC. "크기만 보고 맞히기" 같은 지름길 효과를 뺀 값 |
| bAcc | 실제 정확도와 AI 정확도의 평균. 논문들이 주로 0.5 기준선으로 보고함 |
| 미세조정 | 미리 학습된 큰 모델의 가중치까지 우리 데이터로 더 학습시키는 것. 반대는 "고정(얼림)" |
| LoRA | 큰 모델 전체 대신 작은 덧붙임 부분만 학습시키는 미세조정 방식 |
| 증류 | 크고 느린 "교사" 모델의 점수를 작고 빠른 "학생" 모델이 따라 하도록 학습시키는 것 |
| 정렬 가짜 | 실제 사진을 생성기의 이미지 복원기(VAE)에 한 번 통과시켜 만든 AI 이미지. 내용·크기·형식이 원본과 같아 "생성기 흔적"만 남음 |
| QAT | 8비트로 줄일 것을 미리 고려하며 학습시키는 방식. 학습 후 그냥 8비트로 바꾸면 이 탐지기는 망가짐(측정됨) |
| holdout / 봉인 세트 | 모델을 고르는 데 쓰지 않고 마지막에 한 번만 여는 시험셋 |

### 2-2. 이 표가 말하는 것

1. **OpenFake 같은 "자기 데이터"에서도 저장소가 데이터셋 저자 모델보다 한참 아래입니다.** 데이터셋 버전과 지표가 달라 직접 비교는 안 되지만 방향은 분명합니다. 원인은 분명합니다.
   - OpenFake 학습 파일 608개 중 6개(약 1%)만 썼습니다.
   - 의미 탐지기는 고정된 백본 위에 로지스틱 회귀만 얹었고, 학습량은 이미지 4,000장(원본+증강 8,000행)뿐입니다(`scripts/train_semantic.py`의 `dev_rows`).
2. **헤드라인 수치 0.953에는 지름길이 섞여 있습니다.** 크기 맞춤으로 재면 0.835입니다(`reports/shipped_eval.json`). Reddit은 어느 서브레딧에 올라왔는지로 정답을 붙였기 때문에, "AI 그림체"만 알아봐도 점수가 납니다.
3. **논문 1위 수치는 대부분 ViT-L(약 3억 파라미터)부터 14B 규모에서 나왔습니다.** 가벼운 체급(약 1–2M)의 공개 탐지기는 압축과 SNS 조건에서 거의 전멸합니다. **가볍고 실전에서도 버티는 자리가 비어 있고, 노릴 곳이 바로 여기입니다.**

## 3. 세 설계안 비판

### 3-1. 데이터 우선안

**잘한 점**
- 핵심 원인을 데이터로 직접 짚었습니다. `index.csv`를 세어 보니 약점 생성기는 학습 데이터에 거의 없었습니다(Recraft 0장, Seedream 40장, FLUX.2-klein-9B 0장).
- 평가용 모델 E(시험 생성기를 학습에서 뺌)와 서비스용 모델 P를 나눴습니다.
- 선정용(dev)과 판정용(final) 시험셋을 나눈 방식이 세 안 중 가장 엄격합니다.
- 라벨 정의를 미리 정하고, 판정이 애매한 "회색 지대" 이미지를 따로 둔 것도 좋습니다.

**가장 큰 결함: 가설을 확인하기 전에 비싼 데이터 구축을 너무 많이 쌓습니다.**
- 상업용 실제 사진 15만 장, 공개 모델 생성 9만 장, API 3.5만 장, 외장 SSD 300–400GB를 M1과 병행해 준비합니다. 정작 "작은 모델 + 데이터만으로 충분하다"는 핵심 가설은 M1에서야 판정됩니다.
- 정렬 가짜(VAE 재구성)를 AI로 학습하면서, 신경망 압축(JPEG AI)을 거친 실제 사진을 막을 대책이 없습니다. 회색 지대로 보고만 합니다. 그런데 JPEG AI로 압축한 실제 사진을 탐지기들이 96–97% AI로 판정했다는 보고가 있습니다([2412.03261](https://arxiv.org/abs/2412.03261)).

**수치 지적**
- "학생 학습 1회 $1–3"은 낙관적입니다. 열화 연쇄는 JPEG 인코딩·디코딩을 반복해서 CPU가 병목입니다. 1회 $5–20로 잡는 것이 안전합니다(추정).
- "직접 촬영 외주 ₩200–500만"은 근거가 없습니다(UNVERIFIED).

### 3-2. 모델 우선안

**잘한 점**
- 교사 없이 같은 데이터로 학습한 학생과 비교하는 기준(M4-d)이 있습니다. 증류가 정말 필요한지 검증할 수 있습니다.
- 원본 크기 맞춤 0.835가 노이즈 탐지기 쪽 지름길일 수 있다는 진단이 날카롭습니다. JPEG75로 다시 저장하면 0.913으로 오히려 높아집니다.
- 패치별 보조 손실, 학생을 학습할 때 노트북에서는 교사 점수만 미리 계산해 쓰는 대안도 좋습니다.

**가장 큰 결함: 교사가 지나치게 무겁고, 증류 이득이 증명되지 않았습니다.**
- 교사를 세 겹(DINOv3-L 미세조정, PE-Core-L 미세조정, 선택적으로 7B)으로 쌓고, 학생 학습 중에 교사 토큰까지 따라 하게 합니다. 그러려면 학습 내내 교사 모델을 GPU에서 함께 돌려야 하므로, GPU 비용이 표의 추정보다 커질 수 있습니다.
- 그런데 OpenFake 저자 모델은 SwinV2-Small 하나를 대량 전체 학습한 것만으로 F1 0.992를 냈습니다. 교사가 꼭 필요한지는 아직 모릅니다.
- "L급에서 PE·SigLIP2가 DINOv3-L보다 7–10점 높다"는 근거(TAP, SSAFE)는 고정 상태의 다른 데이터셋 결과입니다. PE는 흐림과 재촬영에 더 약하다는 보고도 있습니다. 가설로만 다뤄야 합니다.

**삭제할 주장**
- "CF ViT-S는 이 저장소 이전 실험에서 2.67% 오탐일 때 43% 탐지": 이전에 시험한 것은 공식 Community Forensics가 아니라 제3자가 만든 파생 모델(`Thermostatic/...-frontier-detector-2026-08`)입니다. 공식 모델은 M0에서 새로 재야 합니다. 데이터 우선안에도 같은 오해가 일부 있습니다.
- "약점 생성기 3종의 지금 탐지율 0–15%": 측정한 적 없는 값입니다. M0에서 생성기별로 잽니다.
- 예상 탐지율 "OpenFake 원본 80–90%": 근거가 약한 낙관치입니다.

### 3-3. 크기·속도 우선안

**잘한 점**
- 오늘 직접 잰 값이 가장 많습니다.
  - NoiseNet은 학습 후 8비트로 바꾸면 AUROC가 0.962에서 0.914로 떨어집니다. 첫 블록만 32비트로 남기면 0.957입니다.
  - DINOv3-B 층별 진단: OpenFake 쪽 신호는 8층에, Reddit 쪽 신호는 12층에 몰려 있습니다.
- 교사가 자기 학습 이미지에 과신하지 않도록 나눠서 점수를 내는 교차 예측을 둡니다.
- 신경망 코덱 증강으로 정렬 가짜와의 충돌을 막고, 그 효과를 JPEG AI 오탐으로 검증합니다.
- 단계식 판정을 두고, 핵심 결과를 "지연 대 탐지율" 그래프로 보여 주는 구성이 좋습니다.

**가장 큰 결함: 30MB·50ms 목표가 검증되지 않은 가정 세 개에 동시에 걸려 있습니다.**
- 세 가정은 다음과 같습니다.
  1. QAT로 정확도 손실을 0.005 이하로 막을 수 있다(확인한 것은 학습 후 양자화 결과뿐).
  2. 8층에서 잘라도 된다(고정 백본 기준 Reddit에서 약 0.03 하락이 측정됨).
  3. 224px 조각 2개면 충분하다(3MP 이미지의 약 3%만 봄).
- 디코딩만 20ms가 걸리는데, 그 시간을 줄일 영역 디코딩도 추정입니다.
- 지연 측정은 부하 때문에 ±30% 오차가 있습니다. 실제로 정적 8비트 4조각(48ms)이 2조각(39ms)과 거의 같게 나왔습니다.
- 동적 8비트 지연(7.5ms 등)은 정확도가 무너지는 방식의 수치라 계획에는 쓸 수 없습니다.

**평가 누수**
- 단계마다 "새 holdout(OpenFake test 5, Reddit 4)에서 한 번씩 판정"합니다. 그러면 하나뿐인 미사용 Reddit 파일을 여러 단계의 결정에 거듭 쓰게 되어, 마지막에는 봉인 세트가 아니게 됩니다.
- "Reddit shard 4–5"라고 했지만, 데이터 우선안이 조회한 HF 파일 목록에 따르면 Reddit test 파일은 0–4번 5개뿐입니다. 5번은 없을 가능성이 높습니다.

### 4-4. 학습 계획

**증강 (두 클래스에 같은 분포로)**
- 강도 단계: 깨끗함 25% / 약함 30%(1–2개) / 중간 30%(3–4개) / 강함 15%(5–6개).
- 연산 목록:
  - 압축: JPEG 40–100, 이중 JPEG, WebP
  - 크기: 0.35–2배 리사이즈(보간 방식 섞음)
  - 흐림, 노이즈, 색·톤 변화, 자르기
  - SNS 사슬: 긴 변 1080/1280/1440/2048 + JPEG 70–90(4:2:0), 1–3회 반복
  - 스크린샷 흉내
  - **신경망 코덱(CompressAI)**
- 강도 하한은 JPEG 40, 0.35배 축소입니다. 정보가 사실상 지워진 이미지를 억지로 맞히게 학습시키지 않기 위해서입니다.

**학생 손실 (교사는 깨끗한 원본 x, 학생은 열화본 x̃를 봄)**
```
L = BCE(정답, s(x̃)) + BCE(정답, s(x))
  + 1.0 · MSE(s(x̃), 교사점수(x))        ← M3에서 효과 판정, 없으면 제거
  + 0.5 · KL(s(x) ‖ s(x̃))               ← 원본·열화본 일관성 (보고된 효과: 왜곡 조건 +9.1점, 깨끗한 조건 −0.9점)
  + 0.2 · 패치 보조 BCE
```

**교사 (단계에 따라 바꿈)**
- M1: 지금 서버 앙상블 점수. 비용 0.
- M2 이후: **DINOv3-7B 고정 + 여러 층 로지스틱 회귀**에 지금 노이즈 탐지기를 더한 것.
  - 교차 예측: 5개 묶음으로 나눠 학습하고, 각 이미지의 점수는 그 이미지를 학습에 쓰지 않은 분류기로 냅니다.
  - 근거: 고정 DINOv3로 처음 보는 상용 생성기를 판정한 정확도가 B 70.3에서 7B 87.5로 올랐습니다([2511.22471](https://arxiv.org/abs/2511.22471)).
  - 7B는 고정 상태에서 JPEG70에 약하므로(AUROC 0.953 → 0.766) **교사에게는 깨끗한 원본만 보여 줍니다.**
- ViT-L LoRA 교사는 7B 교사가 기준에 못 미칠 때만 추가합니다.

**최적화 설정**
- AdamW. 학습률은 백본 5e-5–1e-4, 헤드 1e-3. 층별 학습률 감쇠 0.75, cosine 스케줄, EMA 0.999.
- 4–8 epoch. 4 epoch 뒤에는 어려운 표본(점수가 높은 실제 사진, 점수가 낮은 가짜)을 3배로 다시 뽑습니다.
- 비교 실험: 전체 미세조정과 LoRA를 비교합니다. 좁은 데이터에서 LoRA는 일반화를 망친 사례가 있습니다(Chameleon 0.959 → 0.635).

**기준선 두 개**
- 논문 비교용: 원본 실제 사진의 오탐 1% 지점.
- 서비스용: SNS 처리본이 섞인 보정용 실제 사진 풀에서의 오탐 1% 지점. 지금 Reddit SNS 오탐 3.7% 문제를 겨냥합니다.

  - 회색 지대 칸: JPEG AI, SD-VAE를 거친 실제 사진

  - 중간: **Community Forensics 공식 ViT-S(가장 직접적인 경쟁자)**, AlignedForensics
  - 무거운 쪽: UnivFD, AIDE, Effort, CO-SPY, SPAI, B-Free, DDA, OmniAID, PatchHead·GlobalForge(공개된 경우)
  - 지금 서버

## 5. "압도적 SOTA"가 뜻할 수 있는 것과 없는 것

### 5-1. 근거가 있는 주장 (이길 가능성)

| 주장 | 예상 | 근거 |
|---|---|---|
| 100MB 이하·150ms 이하 체급 1위(NPR, SAFE, CoDA, Tiny-LaDeDa, CF ViT-S 대비) | 높음 | 이 체급은 JPEG50·SNS에서 AI 정확도 0–16%. 대형 탐지기를 ViT-S급으로 증류해 실전 데이터로 평가한 논문은 조사 범위에서 없음 |
| 최신 생성기·SNS 조건, 오탐 1% 고정에서 B-Free·DDA·AIDE·Effort·OmniAID 공식 가중치보다 높음 | 중간–높음 | 이들의 최신 데이터 성적은 AUROC 0.42–0.62, TPR@1%FPR 0–3.8%. **다만 이것은 "데이터의 승리"라고 적어야 정직함** |
| 실제 사진 종류별 오탐 최댓값을 보장(예: 2–3% 이하) | 중간 | 거의 아무도 보고하지 않는 축이라 작은 팀도 차지할 수 있음 |

**발표 문장 템플릿 (M6 기준을 넘을 때만)**

> "파라미터 약 2,300만, M3 CPU에서 3MP 이미지당 약 0.1–0.15초인 탐지기가, 미리 공개한 외부 실전 세트 N개 중 M개에서 공식 가중치를 쓴 공개 탐지기 15종 전부보다 오탐 1% 기준 탐지율이 높고, 데이터셋별 최악값도 가장 높다. 같은 데이터로 다시 학습한 ViT-L 대비로는 X% 수준이다."
